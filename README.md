# 六相机拼接

用终检板桌面上的 7×7 对称圆点标定板，把相机 1（左）到相机 6（右）拼到同一张平面图上，并写出标定文件。

相机 2 的光轴和其他相机大约成 90°。标定板和图纸都在同一张桌面上，所以相邻相机之间仍然是一个平面单应性，不需要把画面硬拉成柱面。

## 数据目录

`260924标定数据` 放在本仓库的上一级，或用 `--data` 指定。每个子目录是一次摆放：

- `相机N`：标定板放在该相机视野里
- `相机N～M`：标定板放在相邻相机的重叠区，目录里通常各有一张图

同一目录里的两张图来自两台相机，不是同一台相机的两次曝光。程序用画面边缘（避开会移动的标定板）把图像归到 6 台相机。

## 算法

1. 检测对称圆点阵。完整板是 7×7；贴着画面边缘时保留能看全的最大子阵。
2. 相邻相机先用图纸上的 SIFT 点估计平面单应，用来消除圆点阵的旋转对称。
3. 同一摆放里两台相机都看到的圆点再拟合一次单应。它和图纸单应一致时，采用圆点单应。
4. 从相机 2→1、3→2 … 6→5 串成投到相机 1 的单应。
5. 每台相机取工位主图，按距离做羽化融合。相机 1 的 +Y 指向相机 6，全景逆时针转 90° 后，相机 1 在左、相机 6 在右。

## 标定文件

标定结果不放进本代码仓库。程序写到 `--out` 目录，默认是运行目录下的 `result/calibration.json`，该目录已加入 `.gitignore`。

- `H_full_to_camera1`：该相机全分辨率像素到相机 1 像素的 3×3 单应，行主序。
- `pairs`：相邻相机的单应、用的是圆点还是图纸、内点数和残差。残差单位是工作尺度像素，乘 `1/working_scale` 得到全分辨率像素。
- `images[].grid_xy_full`：检出的圆心，全分辨率像素。
- 圆心间距在文件里是 1 个网格单位。这组图没有给出物理毫米间距，不能当成已标定的米制外参。

## 构建和运行

需要 Rust、CMake、Visual Studio C++ 工具链，以及 OpenCV 4.11（默认 `C:\opencv\build`）。其他位置用环境变量 `OpenCV_DIR` 指向含 `OpenCVConfig.cmake` 的目录。

```text
cargo run --release -- --scale 0.3
```

可选参数：

```text
sixcam-stitch --data D:\path\260924标定数据 --out result --scale 0.3
```

输出写在 `--out`，不随代码提交：

- `mosaic.jpg`：六相机全景，左为相机 1，右为相机 6
- `overlap_N_on_M.jpg`：相邻相机叠化，用来看对齐
- `calibration.json`：标定结果

语言分工：Rust 负责目录、相机归组、单应链和标定文件；C++/OpenCV 负责读图、圆点、SIFT、变形和融合。
